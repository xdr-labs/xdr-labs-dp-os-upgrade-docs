# DP Ubuntu Upgrade Mirror Manager

This documentation is the operator guide for the current `xdr-labs/ubuntu-mirror-automation` workflow.

The project prepares a single **Ubuntu 24.04 Mirror Server** that downloads and validates the files required for a Stellar Cyber Data Processor (DP) upgrade. DP hosts then retrieve all upgrade material from that Mirror Server over **HTTP/TCP 80**.

```text
Cloudflare R2 ─────┐
                   ├──> Mirror Server ── HTTP/TCP 80 ──> DP hosts
ACPS ──────────────┘
```

DP hosts do **not** need direct access to Cloudflare R2 or ACPS.

## What the current workflow upgrades

The active Full mode performs two ordered phases:

1. **Phase 1 — Ubuntu OS upgrade**
   `16.04 → 18.04 → 20.04 → 22.04 → 24.04`
2. **Phase 2 — DP bringup**
   Bring the DP to **6.6.0** on Ubuntu 24.04.

Ubuntu LTS hops are sequential. Do not skip an intermediate LTS release.

## Choose the correct mode

| DP starting state | Mirror Manager mode | Result |
| --- | --- | --- |
| DP 6.2.x–6.5.0 on Ubuntu 16.04 | **Full OS Upgrade + Phase 2** | Ubuntu 24.04 + DP 6.6.0 |
| Supported DP 6.2–6.5 already on Ubuntu 24.04 | **Phase 2 Only** | DP 6.6.0 |
| Healthy DP 6.6.0 already on Ubuntu 24.04 | Normally no upgrade | No change |

The Phase 2 target in the current application is fixed at **6.6.0**. The starting DP version is detected on the DP host; it is not entered manually on the Mirror Server.

## Operator workflow

On the Mirror Server, use the GUI in this order:

```text
1  Configuration
2  Download and Prepare Upgrade Files
3  Enable HTTP Distribution
4  Verify Upgrade Readiness
7  Show DP Client Upgrade Commands
```

Do not begin the DP-side upgrade until **Verify Upgrade Readiness = PASS**. Use the commands generated by **Menu 7** rather than constructing upgrade commands manually.

## Current architecture

The current product does **not** build a full Ubuntu archive mirror and does **not** use `apt-mirror` as the active upgrade workflow. In Full mode it prepares:

- a selective Ubuntu OS Core data set from Cloudflare R2
- the DP 6.6.0 Phase 2 bundle from ACPS
- signed/validated DP client artifacts
- an nginx HTTP distribution endpoint for DP hosts

This reduces the required Mirror Server storage significantly compared with the older full-mirror design.

## Safety model

Create a **full hypervisor snapshot of every DP VM before the upgrade**. The project does not provide an OS or DP-runtime rollback command.

```text
PROJECT_ROLLBACK_SUPPORTED=NO
OS_ROLLBACK_SUPPORTED=NO
DP_RUNTIME_ROLLBACK_SUPPORTED=NO
RECOVERY_METHOD=HYPERVISOR_SNAPSHOT
```

Intermediate Ubuntu releases are upgrade steps, not recovery points.

## Start here

1. Follow **Quick Start** to install the Mirror Manager.
2. Review **Requirements** and select the correct **Preparation Mode**.
3. Complete the Mirror Manager workflow until readiness reports `PASS`.
4. Use **DP Client Upgrade Commands** for the actual DP-side procedure.
