# Troubleshooting

Identify which layer failed before changing anything:

```text
Configuration → Download/Prepare → HTTP → Readiness → Phase 1 → Phase 2 → Validation
```

## GUI after SSH disconnect

Reopen the existing installation:

```bash
sudo ubuntu-offline-mirror mirror-manager
```

Do not rerun `install.sh` merely to reopen the GUI.

## Menu 2 interrupted

Run Menu 2 again after confirming another copy is not active. Keep reusable partial `.part` files.

## Readiness is NOT READY or FAIL

Recheck saved Configuration, Mirror Server IP, artifact status, nginx, live HTTP files, then run Menu 4 again. Do not start the DP upgrade until `PASS`.

## Mirror Server IP changed

Update Configuration and repeat **2 → 3 → 4 → 7**. Do not reuse old Menu 7 commands.

## Phase 1 is blocked

Transient DNS, HTTP/network, NTP, or apt/dpkg lock problems may be retryable. Integrity/evidence conflicts fail closed. Correct the root cause and follow the current recovery guidance; do not delete `/opt/aelladata/os-upgrade` to hide the state.

## Ubuntu 22.04 looks unhealthy

Jammy is an intermediate state. On affected DP builds, product components can be unavailable or incompatible. Do not repair kubelet/Docker merely to make the transitional state healthy; continue to Ubuntu 24.04 and Phase 2.

## Worker bringup fails

Check worker lists, master-to-worker SSH, the configured common `aella` password, IP/MTU, NTP/DNS, Kubernetes state, and that common staging completed on all nodes before master orchestration.

If destructive recovery cannot be completed safely, restore the approved hypervisor snapshot.
