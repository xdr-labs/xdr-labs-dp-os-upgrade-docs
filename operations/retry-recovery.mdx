# Retry & Recovery

## After an SSH disconnect

Reconnect and run:

```bash
sudo ubuntu-offline-mirror mirror-manager
```

Do not reinstall merely because the terminal disconnected. Continue from the first incomplete menu step. If Menu 2 is still active, wait instead of starting another copy.

## Interrupted downloads

Run Menu 2 again after confirming another job is not active. The workflow reuses valid completed and partial data. Do not delete ACPS `.part` files simply to force a clean retry.

Useful Mirror Server diagnostics:

```bash
ls -lt /var/log/ubuntu-mirror-automation/
cat /etc/ubuntu-mirror/dp-upgrade-mirror.status
```

## DP OS-upgrade state

Phase 1 uses durable state, command journals, checksums, and a controlled state machine. It fails closed when evidence is inconsistent.

Do not delete `/opt/aelladata/os-upgrade` or invent a fresh install over orphaned evidence merely to clear an error. Follow the diagnostic/recovery action recommended by the current release tooling.

## Rollback

The project does not implement OS or DP-runtime rollback commands. If destructive recovery cannot be completed safely, restore the approved pre-upgrade hypervisor snapshot.
