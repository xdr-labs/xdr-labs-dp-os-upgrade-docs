# Clusters and Worker Nodes

For DL/DA clusters with workers, the documented recommendation is to orchestrate workers from their master with `--worker-ips`.

## Recommended order

Complete the DL side before the DA side so DA can register against a healthy DL environment.

At a high level:

```text
DL master + DL workers
        ↓
Validate DL readiness
        ↓
DA master + DA workers
        ↓
Validate full system
```

## Run from each master

On the DL master:

```bash
sudo bash /home/aella/bringup_py3_dp_after_os_upgrade.sh \
  --version 6.5.0 \
  --worker-ips "<dl-worker1-ip>,<dl-worker2-ip>"
```

On the DA master:

```bash
sudo bash /home/aella/bringup_py3_dp_after_os_upgrade.sh \
  --version 6.5.0 \
  --worker-ips "<da-worker1-ip>,<da-worker2-ip>"
```

Add `--skip-download` for the validated dark-site workflow.

## Why use master orchestration?

The master copies or reuses staged artifacts, connects to its workers, and brings them up sequentially. This reduces manual per-worker execution and keeps ordering consistent.

## Manual worker mode

Manual worker bringup is supported by the source runbook but is not the preferred path. If required, use the release-specific `--role` and `--worker-mode` options and run inside `tmux` or `screen` because worker execution runs in the foreground.

Do not parallelize manual worker bringups unless the exact release procedure has been QA-validated for parallel execution.

## Post-join checks

After workers join, verify Kubernetes node readiness, expected role/labels, cluster networking, service health, DNS/NTP, and application readiness before proceeding to the next cluster.
