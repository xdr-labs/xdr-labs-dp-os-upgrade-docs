# Dark-Site Bringup

Use this workflow when the DP has no or restricted Internet egress and the complete 6.5.0 Py3 artifact bundle is staged locally.

## Stage the bundle

The source runbook stages the DP artifacts under:

```text
/opt/aelladata/aelladeb_py3/
```

The bringup script itself is placed under `/home/aella/`.

Typical bundle contents include:

- the 6.5.0 UVP Debian package and checksum
- common Py3 dependencies and checksum
- `bringup_py3_dp_after_os_upgrade.sh`
- the 6.5.0 container image tarball and checksum
- an image manifest list

Use only the release-approved bundle. Verify all supplied checksums before running bringup.

## AIO or master-only command

```bash
sudo bash /home/aella/bringup_py3_dp_after_os_upgrade.sh \
  --version 6.5.0 \
  --skip-download
```

## Cluster master with workers

```bash
sudo bash /home/aella/bringup_py3_dp_after_os_upgrade.sh \
  --version 6.5.0 \
  --skip-download \
  --worker-ips "<worker1-ip>,<worker2-ip>"
```

## Critical checks

Before execution, confirm:

- Ubuntu 24.04 on every DP node
- sufficient free space on `/opt/aelladata` and `/`
- sufficient hypervisor datastore capacity
- healthy NTP and DNS
- static IP addressing
- consistent MTU across the cluster
- master-to-worker connectivity
- a current snapshot or approved backup

## Do not publish credentials

Some internal source runbooks contain environment-specific credentials and shell-escape information. Those values are intentionally excluded from this documentation. Obtain required credentials through the approved internal support channel.

## Monitor

```bash
tail -f /var/log/aella/aella_py3_bringup.log
```

When a run fails, preserve the log, fix the root cause, and re-run the approved command. The documented bringup flow is designed to resume completed work where possible.
