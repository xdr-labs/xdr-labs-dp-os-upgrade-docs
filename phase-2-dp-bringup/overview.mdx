# Phase 2 — DP Bringup

Phase 2 starts only after the DP operating system is Ubuntu 24.04.

The target documented in the current operator materials is **DP 6.5.0 Py3 on Ubuntu 24.04**.

## Standard command

For an AIO or master-only node:

```bash
sudo bash bringup_py3_dp_after_os_upgrade.sh --version 6.5.0
```

For clusters with workers, run the approved `--worker-ips` workflow from the master instead of independently bringing up every worker.

## Connectivity variants

Phase 2 has two variants:

- **Online** — artifacts are downloaded from the approved provisioning source.
- **Dark site / offline** — the complete artifact bundle is pre-staged locally and the command uses `--skip-download`.

## Data preservation

The source guide states that `/opt/aelladata/` is preserved across the upgrade process. This does not replace the requirement for a hypervisor snapshot or backup before the operation.

## Logging

Monitor bringup with:

```bash
tail -f /var/log/aella/aella_py3_bringup.log
```

AIO and master bringups in the documented 6.5.0 flow can continue after an SSH disconnect. If a worker is run manually in worker mode, use `tmux` or `screen` because that foreground execution may not survive a disconnect.

## Re-running

The documented flow is intended to be idempotent. If bringup stops, fix the cause and re-run the same approved command so completed phases can be skipped where supported.
