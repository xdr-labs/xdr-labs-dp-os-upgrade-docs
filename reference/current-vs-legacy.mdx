# Current vs. Historical Guidance

Several internal PDFs and QA runbooks were created while the DP OS upgrade workflow was evolving. They remain useful as historical test evidence, but they do not all describe the current operator workflow.

## Current source of truth

For this site, the current `main` branch of `xdr-labs/ubuntu-mirror-automation` is the primary implementation source.

The current workflow uses:

- **DP 6.6.0** as the fixed Phase 2 target
- one Mirror Manager GUI
- a selective OS Core package from Cloudflare R2 in Full mode
- DP Phase 2 artifacts from ACPS
- nginx HTTP distribution to DP hosts over TCP 80
- generated Menu 7 DP client commands

## Historical procedures

Older documents may describe DP 6.5.0 bringup, `bringup_py3_dp_after_os_upgrade.sh --version 6.5.0`, `apt-cacher-ng` on TCP 3142, traditional full Ubuntu `apt-mirror` servers, or direct Canonical access from every DP.

Those procedures correspond to earlier development/QA stages and should not be mixed into the active Mirror Manager workflow unless engineering explicitly requires a historical path.

Combining commands from different generations can produce incorrect artifact versions, stale server addresses, incompatible package sources, or unsupported recovery behavior.
