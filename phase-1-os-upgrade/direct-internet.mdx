# Direct Internet Upgrade

Use this method when every DP can reach the required Ubuntu repositories directly.

## Required outbound access

The source documentation lists the following services as relevant to the OS upgrade path:

| Protocol / port | Destination | Purpose |
| --- | --- | --- |
| UDP/TCP 53 | DNS | Resolve Ubuntu repository hostnames |
| TCP 80 | `archive.ubuntu.com` | Main and updates repositories |
| TCP 80 | `security.ubuntu.com` | Security updates |
| TCP 80/443 | `changelogs.ubuntu.com` | Release-upgrade metadata |
| TCP 80 | `old-releases.ubuntu.com` | Archived Xenial content when required |
| UDP 123 | Site NTP or public NTP | Time synchronization |
| TCP 443 | `api.snapcraft.io` | Snap-related access if present |

Whitelist repository hostnames rather than fixed IP addresses because Ubuntu services may be CDN-backed.

## Start the automated upgrade

The source guide documents the following automatic OS-upgrade entry point:

```bash
sudo bash bringup_py3_dp_after_os_upgrade.sh --auto-os-upgrade
```

Run the implementation approved for the target release and environment. The automation detects the current LTS state and proceeds through the required hops.

## Monitor progress

```bash
tail -f /var/log/aella/auto_os_upgrade.log
```

After every reboot, confirm that the upgrade service resumes and that the next LTS transition begins normally.

## Recovery

For a transient repository or network failure, restore connectivity and re-run the approved command. Do not skip directly to a later Ubuntu release.
